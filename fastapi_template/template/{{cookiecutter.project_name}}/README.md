# {{cookiecutter.project_name}}

Generated by **NK Backend OS**, a create-to-production FastAPI foundation.
This project includes the product use case, resolved profile, and feature
choices recorded in `platform.yaml`, a typed application shell, and a
generated `nk` CLI.

## Start here

Requirements: Python 3.12+, [uv](https://docs.astral.sh/uv/), and Docker for
profiles that use supporting services.

```bash
# Install generated-project dependencies; this is safe to repeat
uv sync

# Check the generated project
uv run nk doctor
uv run nk validate
uv run nk check

# Start the API; the CLI prints the selected /api/docs URL
uv run nk dev
```

`platform.yaml` is the generated architecture contract. The generator's
use-case mode starts from a product-oriented preset, profile mode records a
complete architecture preset, and interactive mode lets you select every
option. Explicit profile and feature flags remain available for advanced
composition. The generation summary and this manifest should agree before the
service is deployed.

The API documentation surfaces are:

- `/api/docs` — API Studio with editorial docs and request builder
- `/api/swagger` — interactive Swagger explorer
- `/api/redoc` — reference-oriented ReDoc view

The generated project logo is served from
`/static/branding/logo.png`; replace that asset to apply your own branding.

## Project profile

Inspect `platform.yaml` to see the exact choices made during generation:
the requested `use_case`, resolved `profile`, API type, database, ORM, CI,
messaging, identity, observability, AI, and industry modules. Product-oriented
use cases currently select the closest existing platform profile; they do not
claim that domain-specific CRM, data, or high-scale modules are generated
automatically. The generated code is intentionally modular so you can remove
or extend individual integrations without changing the application entry
point.

## Docker

Compose is split into base + overlays:

| File | Role |
| --- | --- |
| `docker-compose.yml` | Base topology and internal service network |
| `docker-compose.dev.yml` | Reload, source mounts, and local service ports |
| `docker-compose.prod.yml` | Production-shaped stack without source mounts |

For local development:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

Use `uv run nk dev --otlp` when the project includes OpenTelemetry support.
Set `GRAFANA_ADMIN_PASSWORD` before starting that overlay.

If `nk dev` finds an existing Compose stack, it asks whether to reuse it or
start a new isolated stack. Use `uv run nk dev --reuse` or
`uv run nk dev --new` to choose non-interactively. A new stack gets its own
Compose project, network, volumes, images, and automatically selected host
ports.

For a production-shaped local stack:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Service DNS inside the stack uses Compose names such as `db`, `redis`, `rmq`,
`kafka`, `nats`, and `api`. Credentials come from `.env`; replace local
development values before using the stack outside a private development
environment. The production overlay clears the broad `.env` injection used by
the base stack and requires explicit credentials and host policy variables:

```bash
ALLOWED_HOSTS='["api.example.com"]' \
CORS_ALLOWED_ORIGINS='["https://app.example.com"]' \
DB_USER='service_user' \
DB_PASSWORD='secret-manager-value' \
DB_ADMIN_USER='migration_admin' \
DB_ADMIN_PASSWORD='separate-secret-manager-value' \
DB_OWNER_ROLE='service_owner' \
DB_NAME='service' \
USERS_SECRET='32-byte-secret-manager-value' \
AUTH_STORE_BACKEND='redis-or-sql' \
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Never use the development overlay, `guest/guest`, empty Redis passwords, or
predictable project-name database passwords in production. Business, cache,
broker, GraphQL, SCIM, file, and metrics routes require authentication when
identity is enabled; health and readiness are the only public operational
probes by default. Cookie-session mutations require `X-CSRF-Token`.

Rebuild whenever `uv.lock` or `pyproject.toml` changes:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml build
```

## Observability

When OpenTelemetry is enabled, the self-hosted observability overlay starts
an OpenTelemetry Collector, Prometheus, Loki, Tempo, and Grafana. Application
telemetry stays on the internal Docker network; Grafana is mapped to localhost
only.

Like this:

```bash
GRAFANA_ADMIN_PASSWORD='replace-this' \
docker compose -f docker-compose.yml -f docker-compose.prod.yml \
  -f deploy/docker-compose.otlp.yml up -d --build
```

Open Grafana at http://localhost:3000/ and change the default administrator
credentials before exposing it through an edge proxy. Prometheus scrapes the
single internal `/api/metrics` endpoint; do not publish Prometheus, Loki, Tempo,
or the collector directly.

You can read more about OpenTelemetry here: https://opentelemetry.io/

## Migrations

If you want to migrate your database, you should run following commands:
```bash
{%- if cookiecutter.orm in ['sqlalchemy', 'ormar'] %}
# To run all migrations until the migration with revision_id.
alembic upgrade "<revision_id>"

# To perform all pending migrations.
alembic upgrade "head"
{%- elif cookiecutter.orm == 'tortoise' %}
# Upgrade database to the last migration.
aerich upgrade

{%- elif cookiecutter.orm == 'piccolo' %}
# You have to set a PICCOLO_CONF variable
export PICCOLO_CONF="{{cookiecutter.project_name}}.piccolo_conf"
# Now you can easily run migrations using 
piccolo migrations forwards all
{%- endif %}
```

### Reverting migrations

If you want to revert migrations, you should run:
```bash
{%- if cookiecutter.orm in ['sqlalchemy', 'ormar'] %}
# revert all migrations up to: revision_id.
alembic downgrade <revision_id>

# Revert everything.
 alembic downgrade base
{%- elif cookiecutter.orm == 'tortoise' %}
aerich downgrade
{%- endif %}
```

### Migration generation

To generate migrations you should run:
```bash
{%- if cookiecutter.orm in ['sqlalchemy', 'ormar'] %}

# For empty file generation.

{%- elif cookiecutter.orm == 'tortoise' %}

{%- endif %}
```
